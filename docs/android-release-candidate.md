## Android manual acceptance checklist

- [ ] On a narrow Android screen, open Privacy Policy before signup; sign up/login, wrong credentials and network failure all show usable messages. Missing/deep-link pages recover to the correct home/login without horizontal clipping.
- [ ] Discovery, theme, map dragging/zoom/pins, tab navigation, search, saved venues, reviews and posting retain expected behavior. Hide/show and resize the map without a camera jump. Genuine empty search differs from unavailable/offline; retry keeps useful cached state.
- [ ] Only the real client advertises bookings after the assigned owner verifies real active inventory. No fallback tables appear on errors. Two customers competing for the same table produce one claim.
- [ ] Invalid name/email/Philippine phone and past/invalid arrival are rejected by direct API too. Server-derived slots match exact arrival minutes and client schedules at boundaries.
- [ ] No method attached, checkout interruption, app kill/background and abandoned checkout all release the hold after five minutes. Synthetic manual proof starts one thirty-minute review deadline; retries do not extend it. Owner approval is idempotent; expired/late approval cannot reclaim a table.
- [ ] Customer B/unrelated owner/anonymous cannot read A's private activities/proof/documents. Assigned owner sees only applicable proof; admin access is authorized. Test direct REST/RPC/Storage URLs and overlapping permissive policies, not just UI filtering.
- [ ] Execute all PayMongo **test-mode** journeys in the payment document. Duplicate/wrong/delayed events cannot double-apply or alter original `paid_at`; paid-after-cancellation goes to resolution/refund review. Return URLs alone never mark paid. Reconcile provider success/local failure before enabling tests.
- [ ] Photos with representative human faces are obscured before posting. Authentication, size/MIME rejection, predictable 429, queue saturation, timeout, cleanup, interruption/retry and private ownership all work on the real staging service. Blank-image smoke tests do not prove face quality.
- [ ] Circle sharing starts off, opt-in publishes only to current members, Stop clears remotely and invalidates queued GPS updates, and Leave removes membership/rotates invites/transfers ownership. Offline members cannot be forced to erase an old cache until reconnecting; verify refresh after reconnect.
- [ ] On disposable accounts, deletion blocks active obligations, requires fresh authentication, survives 202/retry/app restart/storage/Auth failures, removes personal files/posts/profile and transfers groups, denies the old JWT, and retains de-identified ledger counts/amounts/provider IDs/`paid_at`. Check the actual distributed late-upload race before accepting deletion.
- [ ] Native reservation reminders are scoped to the correct account; logout/account switching cancels inappropriate reminders. Validate native modules in an APK, not Expo Go alone.
- [ ] With the APK stopped and running, malformed percent-encoded and oversized external links recover to home promptly; valid payment, OAuth and Unicode links retain their normal behavior. Check this on the installed APK, not only the local Router hook adapter.

## Rollback

Keep a known-good **staging** APK/Render artifact reference and schema/Storage backup before deployment. For a UI regression, redeploy the prior staging admin artifact or reinstall the prior compatible staging APK. Do not restore the old public customer/owner web distribution.

For a booking/payment/upload regression, disable the affected feature in staging and repair forward while preserving restrictive policies, private buckets, bounded holds, idempotency records, event inbox and retained ledger. Do not drop migrations/tables, remove guards, recreate checkout attempts or automatically replay stale unknown provider calls. Reconcile open provider sessions and events using the payment document before restarting.

For deletion, stop starting new jobs and repair existing jobs; removed personal data/Auth accounts are not restored by reverting code. Preserve deletion access guards. Restoring an existing database/Storage backup, production rollback, financial transactions, credential rotation and Git-history rewriting are explicit high-risk boundaries requiring a separate approved operation. No such action was performed here.
